# 09 — Live Test Store Contamination and Isolation Safeguards

Status: current
Audience: maintainers, contributors

Empirical investigation into test fixture leakage into the operator's live
state store (`~/.local/state/agy-mcp`), diagnosis and safe cancellation of 40
ghost-queued records blocking job concurrency, implementation of multi-layered
test harness isolation guards, and creation of the safe fixture cleaner
`cleanup_fixtures.py`.

## Question

How did test fixture jobs leak into the operator's live state directory, what
operational risk did stale and ghost-queued records pose to job concurrency,
and what multi-layered isolation safeguards and cleanup mechanisms prevent test
pollution from touching live state?

## Method

Investigated across two linked phases:
1. **Stale Jobs Diagnosis and Remediation (2026-10-29):**
   Read-only diagnosis and metadata backup of the live state directory
   `~/.local/state/agy-mcp` taken at `2026-10-29T19:20:02Z` (backup directory
   `~/agy-state-backup-20261030-005002`). Analysis characterized all 332
   discovered `job.json` records by state, age, process liveness, and repository
   path. Safe remediation was executed at 19:34Z via `JobManager.cancel()`
   (`server.py:334`) on 40 ghost-queued records.
2. **Isolation Audit and Guard Hardening (2026-10-31):**
   Conducted on branch `fix/test-isolation` based on `main` (`23bb1aa`). Traced
   the resolver path in `src/agy_mcp/jobs.py:28-34` (`get_base_state_dir`),
   identified pre-fix leak call sites, and constructed an in-process resolution
   guard, a `tests/conftest.py` bootstrap redirect, `/proc/self/fd` syscall
   wrappers for `dir_fd` operations, and a dedicated candidate cleaner
   `src/agy_mcp/cleanup_fixtures.py`.

## Result

### 1. Diagnosis of Live Store Contamination (2026-10-29 Snapshot)

The live state directory contained 332 total `job.json` records:

| State | Count | Age Range (h) | Live Process | Repository Ownership |
|---|---:|---|---:|---|
| `failed` | 272 | 70.7–87.0 | 0 | pytest temp: 272 (`/tmp/pytest-of-<user>/...`) |
| `queued` | 40 | 2.1–2.7 | 0 | pytest temp: 40 (`/tmp/pytest-of-<user>/...`) |
| `done` | 15 | 35.9–84.6 | 0 | clipsync-lab: 13, agy-scratch: 2 |
| `needs_review` | 5 | 4.7–74.6 | 0 | clipsync-lab: 5 (all dead PIDs) |

Overall repository ownership among the 332 records:
- **312 pytest temp repositories:** all generated by test fixture runs under `/tmp/pytest-of-<user>/pytest-*/.../repo`.
- **18 clipsync-lab repositories:** user projects.
- **2 agy-scratch repositories:** user projects.

### 2. Concurrency Jam Root Cause

The wrapper limits active concurrency via `max_concurrent_jobs` (default 2, configured in `src/agy_mcp/config.py:35`).
Active jobs are computed by `jobs.py:249-261` (`count_active_jobs`), which counts jobs in `{queued, running}`.

The 40 `queued` records were created by test suites where `create_job` calls omitted an explicit `base_state_dir`:
- `tests/audit/test_audit_baseline.py` (historical lines 36, 73, 121; pre-fix lines 42, 74, 122 in `aaf7408^`)
- `tests/verify/test_verify_args.py` (historical line 62; pre-fix line 65 in `aaf7408^`)

Because `create_job(base_state_dir=None)` defaulted to `jobs.get_base_state_dir(None)`, the initial `job.json` was written to the live operator directory `~/.local/state/agy-mcp/jobs/<job_id>` in `queued` state. The tests then supplied a temporary `state_dir` for subsequent execution, leaving the live record permanently abandoned in `queued` with `pid=null`.

Ten pytest sessions creating 4 leaked jobs each produced exactly 40 ghost `queued` records. Because the background server had started on Tue Oct 27 at 02:24:07 (PID 1099171), before these records were created, startup recovery (`recovery.reconcile_on_startup()`) had not run to transition them to `failed`. Consequently, `count_active_jobs` returned 40, completely exhausting the concurrency limit of 2 and blocking all new production jobs.

### 3. Remediation and Safe Cancellation

The 40 ghost `queued` records were cancelled individually using `JobManager.cancel()`.
- **Pre-cleanup state:** 272 failed, 40 queued, 15 done, 5 needs_review; `total_active_jobs=40`.
- **Post-cleanup state:** 272 failed, 40 cancelled, 15 done, 5 needs_review; `total_active_jobs=0`.
- **Store disk usage:** 12,209,019 bytes before; 12,215,659 bytes after (40 cancelled records retained on disk until 14-day retention pruning).

### 4. Multi-Layered Isolation Safeguards

To ensure test suites can never resolve or touch live operator state:
1. **Conftest bootstrap redirect (`tests/conftest.py`):** Captures real state directory at initial import in `_AGY_MCP_CAPTURED_REAL_LIVE_STATE`, redirects `HOME`, `XDG_STATE_HOME`, and `AGY_MCP_STATE_DIR` to a temporary directory before test modules import.
2. **Resolution guard:** `agy_mcp.jobs.get_base_state_dir` raises `RuntimeError("live agy-mcp state")` if resolving the operator's real state directory or any path underneath it.
3. **Write barrier:** `sys.addaudithook` blocks mutating filesystem calls under live state with `"BLOCKED by test isolation guard"`.
4. **`dir_fd` syscall wrappers:** Review identified that `sys.audit` does not expose directory file descriptors for relative path arguments. Wrappers resolving file descriptors through `/proc/self/fd` were added for `os.open`, `os.unlink`, `os.rmdir`, `os.mkdir`, `os.chmod`, `os.chown`, `os.utime`, `os.symlink`, `os.link`, `os.rename`, and `os.replace`.
5. **Repo root exemption:** Checked-out repository root (`_REPO_ROOT`) is exempted so pytest can write pyc/cache files during worktree verification.
6. **AST verification:** Static scan confirmed 0 calls to `JobManager` or `create_job` omit `base_state_dir` across `tests/**/*.py`.

### 5. Safe Fixture Cleaner (`cleanup_fixtures.py`)

A conservative CLI tool (`python -m agy_mcp.cleanup_fixtures`) was implemented under [D87](../design/decisions.md#d87-safe-fixture-row-listercleaner-cleanup_fixtures-candidate-signature-and-safety-contract) and [D88](../design/decisions.md#d88-safe-fixture-cleaner-fixes-fail-closed-scan-keysubstring-protection-pre-delete-revalidation-honest-manifest):
- `--store PATH` is mandatory; dry-run by default; `--yes` required for deletion.
- Candidate signature requires ALL of: canonical lowercase UUID directory under `store/jobs/`, valid `job.json` <= 1 MiB, terminal state (`done`, `failed`, `cancelled`), `repo_path` matching `tempfile.gettempdir()` + `pytest-of-*` -> `pytest-<n>` -> `test_...`, store and repo on distinct basetemps, non-live PID, age > threshold, no symlinks, and no follow-up edge from a kept job.
- Pre-delete atomic manifest written to `store/jobs/.cleanup-manifest-<UTC>.json` before removing directories.
- 10 review defects repaired across Round 1 (including `dir_fd` bypass, reload sentinel, and unparseable timestamp fallback).

## Conclusion

Test isolation requires defense-in-depth spanning environment variable redirection, resolution-time assertions, and kernel-level audit hooks. Under [D86](../design/decisions.md#d86-test-harness-live-state-isolation-guard-and-conftest-bootstrap-redirect), [D87](../design/decisions.md#d87-safe-fixture-row-listercleaner-cleanup_fixtures-candidate-signature-and-safety-contract), [D88](../design/decisions.md#d88-safe-fixture-cleaner-fixes-fail-closed-scan-keysubstring-protection-pre-delete-revalidation-honest-manifest), and [D99](../design/decisions.md#d99-non-git-cleaner-hardening-iterative-json-depth-caps-duplicate-key-rejection-in-fixtures-storeproject-argument-validation-and-process-group-liveness):
1. Test execution is structurally quarantined from `~/.local/state/agy-mcp` at import time.
2. Direct resolution of live state paths raises `RuntimeError`.
3. Fixture rows in test stores are purged strictly via opt-in, fail-closed signature verification with pre-delete manifest tracking.
