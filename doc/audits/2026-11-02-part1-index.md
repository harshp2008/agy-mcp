## Verdict in six sentences

The complaint that this is "AI-written code with weak structure" is **partly
right for the wrong reasons**. Layout is the real problem: a flat 24-module
package where 13 files exceed 500 lines, a user-facing cleaner that imports its
private helpers from a pytest-fixture cleaner, and 73% of the tracked
repository being archived run evidence. Dead code is **not** the problem: ruff
(`E,F,I,T20`) is clean, there is not one `TODO`/`FIXME` or commented-out line,
and exactly five module-level symbols have zero references. Docs are **not** the
problem either: all 24 modules have docstrings and 86.6% of functions do, with
an unusually good "what it owns / what it must never do" style; the gaps are
narrow and sit exactly in the two hardest places (`server.py` 63% and
`verify.py` 70%). Complexity is concentrated, not pervasive: two functions
(`_check_worktree_status` 473 lines/115 branches, `_finalize_terminated_process`
588/126) carry most of it, plus a 204-line config validator nested 17 deep. Tests
are the least structured part: 887 of 1,711 cases (52%) test one module, named
by fix round (`fixes`, `fixes2` … `fixes10`, `f1`…`f28`), with 12 files frozen
by `sha256` that I measured but could not find committed as a manifest.

## What is actually wrong (ranked by damage per hour of work)

1. **Layout/packaging**: flat package, cleaner↔fixture-cleaner coupling, evidence
   store as 73% of the repo, no CI (A1, A2, A3, A6, G4).
2. **Two monster functions** in the destructive paths (`_check_worktree_status`,
   `_finalize_terminated_process`) (D1, D2).
3. **Module-boundary violations**: `models.py` decides policy, `manager.py` owns
   resume policy, `server.py` is 350 lines of copy-paste, `cleanup_jobs.py`
   re-implements `job.json` validation five times (B4, B3, B5, C3).
4. **Test naming/ownership**: round-numbered files, half the suite on one module,
   no committed freeze manifest (F1, F2, F6).
5. **Small, cheap wins**: five dead symbols (one already drifted from live logic),
   one duplicated helper, a permanently-ignored lint rule for a frozen test
   (C1, C2, C7).
