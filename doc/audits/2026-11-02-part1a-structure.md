## A1 — `src/agy_mcp/` is a flat 24-module package holding 16,112 lines

**Severity:** high · **Effort:** L · **Risk of action:** medium

Evidence:

```
$ ls src/agy_mcp/*.py | wc -l
24
$ wc -l src/agy_mcp/*.py | tail -1
  16112 total
$ ls src/agy_mcp
__init__.py  __main__.py  audit.py  cli_log.py  cleanup_fixtures.py
cleanup_jobs.py  config.py  gitops.py  jobs.py  manager.py  models.py
parse_result.py  preamble.md  recovery.py  runner.py  scratchpad.py
server.py  states.py  supervisor.py  transcript.py  usage.py  util.py
verify.py  watcher.py  worktree.py
```

There are no subpackages. A reader cannot tell "server plumbing" from
"cleanup CLIs" from "orchestration core" from the directory listing alone;
the only grouping is the imported `docs/CODEMAP.md`.

The important structural fact is not the flatness itself but that the flat
directory hides three different kinds of code:

| Kind | Modules | Lines |
|---|---|---|
| Orchestration core (one job lifecycle) | `manager`, `supervisor`, `recovery`, `runner`, `worktree`, `gitops`, `watcher`, `verify`, `audit`, `transcript`, `cli_log`, `parse_result`, `usage`, `scratchpad` | 10,432 |
| Server/tool surface | `server`, `models`, `states`, `config`, `jobs`, `util` | 3,089 |
| Standalone cleaners (own CLIs) | `cleanup_jobs`, `cleanup_fixtures` | 2,568 |
| Package dunders | `__init__`, `__main__` | 23 |

Sum: 16,112 (`wc -l src/agy_mcp/*.py`); per-module counts in
`~/agy-review/audit/metrics-src.json`.

A flat layout is defensible for 24 modules; what is *not* defensible is that
`cleanup_jobs.py` (a CLI that is not used by the server at all) sits next to
`manager.py` (imported by `server.py`), and that the two cleaners import each
other's private helpers (A2).

**Proposed action:** adopt the *moderate* tree in §A9 — two subpackages
(`cleanup/`, `server/`) and two new policy modules — not a wholesale
`core/`-`orchestration/` re-layout. **Do not move the 14 orchestration modules**;
their names are already accurate and moving them creates 527-file doc churn for
zero comprehension gain.

# A9 — Target tree (moderate; recommended)

Keeps every orchestration module where it is. Creates groups only where the
code genuinely works together.

```
src/agy_mcp/
├── __init__.py            # unchanged
├── __main__.py            # unchanged (python -m agy_mcp)
├── server.py              # unchanged: FastMCP tools + CLI bootstrap
├── models.py  states.py  config.py  jobs.py  util.py      # unchanged
├── manager.py  supervisor.py  recovery.py  runner.py      # unchanged
├── worktree.py  gitops.py  watcher.py  verify.py          # unchanged
├── audit.py  transcript.py  cli_log.py  parse_result.py   # unchanged
├── usage.py  scratchpad.py                                # unchanged
├── cleanup/                     # NEW subpackage (2,568 lines move here)
│   ├── __init__.py
│   ├── store_io.py              # canonical UUID, safe JSON+limits, PID/PGID,
│   │                            #   symlink scan, manifest writer, safe delete
│   ├── worktree_status.py       # git metadata readers + _check_worktree_status
│   ├── jobs_cli.py              # classify + run_cleanup + parse_args + main
│   └── fixtures_cli.py          # fixture signature classifier + run_cleanup
├── jobs_cli_compat.py           # OPTIONAL shim, see breakage table R1
└── data/preamble.md             # moved from package root
```

The alternative *aggressive* tree (`core/`, `orchestration/`, `policy/`,
`server/`) was evaluated and rejected: it moves 14 modules whose names are
already correct, invalidates the AST baseline for the whole package, forces a
rewrite of `docs/CODEMAP.md`'s 752 lines, and buys no reading benefit.
Recorded here so the decision is explicit rather than absent.
